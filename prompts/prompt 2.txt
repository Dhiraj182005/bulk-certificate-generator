Implement the database models and Alembic migrations for the Bulk Certificate Generator.

Use SQLAlchemy 2.x declarative models and proper foreign keys.

Create two tables:

1. GenerationJob:
- UUID primary key
- Status: queued, processing, completed, partially_completed, or failed
- Total recipient count
- Success count
- Failure count
- Created and updated timestamps

2. Certificate:
- UUID primary key
- Foreign key to GenerationJob
- Recipient name and email, nullable when individual input is invalid
- Status: pending, processing, completed, or failed
- Generated PDF file path, nullable until generation succeeds
- Error message, nullable unless generation fails
- Created and updated timestamps

A job has many certificates. Configure ORM relationships and appropriate indexes.

Use string-backed status values or Python enums with portable database behavior. Avoid database-specific features that make SQLite testing difficult.

Tasks:
- Configure Alembic to read the application's database URL and model metadata.
- Generate the initial migration.
- Verify that upgrade and downgrade operations work.
- Ensure generated file paths and recipient information are persisted correctly.
- Do not create database tables automatically at application startup.

Use a local PostgreSQL database for development. Do not run destructive migrations against any existing user database.

Run available migration and import checks. Report the exact commands and results.
